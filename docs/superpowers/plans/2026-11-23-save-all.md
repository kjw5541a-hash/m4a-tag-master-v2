# 큐 화면 [모두 저장] Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (사용자가 인라인 실행을 골랐다). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 큐(홈) 화면 버튼 하나로 분석이 끝난 곡들을 공유 시트(없으면 다운로드)로 한 번에 내보내고 카드를 '저장됨'으로 바꾼다.

**Architecture:** 저장 대상·막힘 판단은 store.ts의 순수 함수, 공유는 save.ts의 `shareOrDownload`를 파일 배열로 넓혀 편집 화면과 같이 쓴다. QueueScreen이 탭 핸들러 안에서 await 없이 `buildOutput`을 돌려 파일을 만들고 바로 공유한다.

**Tech Stack:** React 19, zustand 5, TypeScript, node:test, Playwright(Chrome) e2e

**Spec:** `docs/superpowers/specs/2026-11-23-save-all-design.md`

## Global Constraints

- 공유는 탭 핸들러 안에서 await 없이 연다(iOS 사용자 제스처). 파일 만들기는 그 전에 동기로 끝낸다.
- 한 번 공유에 최대 10곡(`SHARE_BATCH = 10`).
- `navigator.share`에 `title`·`text`를 넣지 않는다.
- 주석·화면 문구는 한국어. `git add`는 파일 이름을 적어서.

## Review Focus

- 검색·분석이 남은 곡이 있으면 버튼이 꺼져 있어야 한다 → Task 1 단위 테스트.
- '저장됨' 곡이 '다시 분석' 중이면 그것도 막아야 한다(끝나면 '저장 필요'로 돌아가므로) → Task 1 단위 테스트.
- 읽기에 실패한 곡(status 'failed')은 대상도 아니고 막지도 않는다 → Task 1 단위 테스트.
- 공유를 취소하면 아무 곡도 '저장됨'이 되지 않는다 → Task 2 단위 테스트('cancelled'), Task 3은 'cancelled'일 때 markSaved를 부르지 않음.
- 여러 파일이 공유 한 번으로 넘어간다 → Task 2 단위 테스트, Task 3 e2e.

### Task 1: 저장 대상 고르기 + 곡 오류 기록

**Files:**
- Modify: `src/store.ts` (statusLabel 아래에 함수, Queue 인터페이스와 구현에 `setError`)
- Test: `src/store-analysis.test.ts`

**Interfaces:**
- Produces: `export function saveAllTargets(items: Item[]): { ready: Item[]; busy: boolean }`
  - `ready` = 큐 순서대로 `status === 'review'`인 곡
  - `busy` = 어느 곡이든 `status`가 'reading'·'searching'이거나 `analysisJob?.state`가 'waiting'·'running'
- Produces: Queue 액션 `setError(id: string, error?: string): void` (해당 곡 `error`만 바꿈)

- [ ] **Step 1: 실패하는 테스트** `test('saveAllTargets: 저장 필요 곡만 고르고, 검색·분석이 남으면 busy')`
  - Item을 `{ id, fileName: 'x.m4a', status, analysisJob }`로 만들어(`as Item`) 확인:
    - review+done, review+failed, review+skipped, saved+done, failed(작업 없음) → ready는 review 세 곡(순서 그대로), busy false
    - 위에 reading 한 곡 추가 → busy true
    - 위 기본에 searching 한 곡 추가 → busy true
    - 위 기본에 review+waiting 한 곡 추가 → busy true이고 그 곡도 ready에 들어감
    - 위 기본에 saved+running 한 곡 추가 → busy true, ready는 그대로 세 곡
- [ ] **Step 2:** `node --test src/store-analysis.test.ts` → saveAllTargets 없음으로 FAIL
- [ ] **Step 3:** `saveAllTargets`, `setError` 구현 (`setError: (id, error) => patch(id, { error })`)
- [ ] **Step 4:** `node --test src/store-analysis.test.ts` → PASS
- [ ] **Step 5:** 커밋 `git add src/store.ts src/store-analysis.test.ts`

### Task 2: 공유를 파일 여러 개로 + 저장 오류 문구 공유

### Task 3: 큐 화면 버튼 + e2e

**Files:**
- Modify: `src/ui/QueueScreen.tsx`, `scripts/e2e.ts`

**Interfaces:**
- Consumes: `saveAllTargets`, `setError`, `markSaved`(store), `buildOutput`, `shareOrDownload`, `saveErrorMessage`, `SHARE_BATCH`(save)

**동작:**
- `ready.length === 0 && !busy`면 버튼을 그리지 않는다. 목록(`ul`) 아래, 빌드 표시 위에 둔다.
- 문구: `ready.length <= SHARE_BATCH`면 `모두 저장 (N곡)`, 넘으면 `10곡 저장 (남은 N곡)`. (설계의 '나머지 저장' 대신 상태 없는 문구로 정함 — 첫 10곡 뒤 남은 수가 10 이하면 다시 '모두 저장 (N곡)'.)
- `busy || saving || ready.length === 0`이면 disabled. busy면 버튼 아래 `분석이 끝나면 저장할 수 있어요`.
- 탭: `ready.slice(0, SHARE_BATCH)`마다 `buildOutput(item.source!, item.edit!)`를 try로 감싸 성공은 `{ id, file }` 목록, 실패는 `setError(id, '저장을 막았어요(원본은 안전해요): ' + 메시지)`. 성공이 0개면 끝. 아니면 `saving` 켜고 `shareOrDownload(files)` → 'cancelled'가 아니면 각 곡 `markSaved(id, file.name)`, 오류면 화면 알림에 `saveErrorMessage(err)`, finally `saving` 끔.

- [ ] **Step 1: e2e 추가** (기존 흐름 끝, '저장됨' 확인 뒤)
  - `page.evaluate`로 `navigator`에 `canShare: () => true`, `share: async ({ files }) => { window.__shared = await Promise.all(files.map(async (f) => ({ name: f.name, bytes: [...new Uint8Array(await f.arrayBuffer())] }))) }`를 정의
  - 픽스처 두 개(기존 ffmpeg 호출을 파일 이름만 바꿔 두 번)를 `setInputFiles([a, b])`
  - `getByRole('button', { name: '모두 저장 (2곡)' })`가 enabled 될 때까지 기다림(timeout 60s) → 클릭
  - `window.__shared` 길이 2, 각 바이트를 `readTags` → `parseAnalysis(tags.analysis)`가 있음
  - '저장됨' 카드가 3개(`getByText('저장됨')` count 3), 버튼은 사라짐
