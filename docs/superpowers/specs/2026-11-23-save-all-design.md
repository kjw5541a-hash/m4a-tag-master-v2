# 큐 화면 [모두 저장] — 짧은 설계

## 의도

여러 곡을 넣고 분석이 끝나면 곡마다 편집 화면에 들어가지 않고 큐(홈)에서 한 번에 저장한다. 기획서 3장 S2, 5.7 '일괄 저장', 6장 A 화면의 '일괄 저장'에 해당한다.

## 목표 / 비목표

- 목표: 큐 화면 버튼 하나로 저장 대상 곡을 공유 시트(없으면 다운로드)로 내보내고 카드를 '저장됨'으로 바꾼다.
- 비목표: M4의 나머지(자동 확정, Wake Lock, visibilitychange 안내, 검색 동시 2개). 이번에 넣지 않는다.
- 피할 것: 일부 곡만 조용히 빠진 채 저장되어 어떤 곡이 남았는지 헷갈리는 것.

## 제약

- iOS `navigator.share`는 탭 직후에만 열린다. 파일 만들기(writeTags·verify)는 탭 핸들러 안에서 await 없이 끝낸다.
- 공유는 탭 한 번에 한 번. 10개 넘게 한 번에 공유하는 것은 실기기 미확인이라 10개씩 나눈다(기획서 5.7).
- `title`·`text`는 넣지 않는다(텍스트.txt 생김).

## 방식

| 방식 | 장단점 |
|---|---|
| **A. 큐 화면 버튼, 한 번 공유에 최대 10곡 (선택)** | 기획서와 같음. 공유 시트 '파일에 저장' 한 번으로 한 폴더에 들어감. 11곡 이상은 버튼을 한 번 더 누름 |
| B. 곡마다 공유 시트를 차례로 연다 | 탭마다 한 번만 열 수 있어 곡 수만큼 눌러야 함. 편집 화면에서 저장하는 것과 다를 바 없음 |
| C. zip으로 묶어 한 파일 저장 | 의존성 추가, MAPP에서 바로 못 읽음 |

사용자가 A를 골랐다(2026-11-23).

## 정한 것

- 대상: `status === 'review'`이고 분석이 끝난 곡(analysisJob이 done·failed·skipped). 'saved' 곡은 다시 넣지 않는다.
- 막음: 읽는 중·검색 중이거나 분석이 대기·진행 중인 곡이 하나라도 있으면 버튼을 끄고 "분석이 끝나면 저장할 수 있어요"를 보여 준다.
- 버튼 이름: 대상 10곡 이하 `모두 저장 (N곡)`. 11곡 이상이면 앞 10곡을 저장하고, 남은 것이 있으면 다음 탭에서 `나머지 저장 (N곡)`. 큐 아래쪽에 둔다.
- 결과: shared/downloaded면 넣은 곡 모두 markSaved. 취소(AbortError)면 아무것도 바꾸지 않음. NotAllowedError면 "한 번 더 눌러 주세요".
- 검증 실패 곡: 그 곡만 빼고 나머지를 저장하고, 그 곡 카드 error에 이유를 남긴다.
- 코드 재사용: 파일 만들기는 `buildOutput`, 공유는 `shareOrDownload`를 파일 배열을 받도록 바꿔 둘 다 쓴다. 다운로드 대체 경로는 파일마다 `<a download>`.
