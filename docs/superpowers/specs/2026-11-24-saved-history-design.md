# 저장 기록으로 중복 저장 막기 — 짧은 설계

## 의도

사용자 보고(2026-11-24): 음악 앱에 같은 제목이 여러 개, '파일' 앱에는 `제목 2.m4a`, `제목 3.m4a`. 만든 시각이 어제·오늘 → 같은 곡을 날을 바꿔 다시 넣고 다시 저장한 것. '파일'은 같은 이름을 덮어쓰지 않고 번호를 붙이고, 앱은 폴더를 볼 수 없으며 큐는 앱을 닫으면 비므로 이미 저장한 곡인지 몰랐다. 사용자가 방식 A(이 기기에 저장 기록)를 골랐다.

## 목표 / 비목표

- 목표: 이 앱으로 저장한 곡의 원본 파일과 결과 파일을 다시 넣으면 바로 '이전에 저장함 (M/D)'로 보이고, 검색·분석을 하지 않으며 [모두 저장]에서 빠진다.
- 목표: 같은 파일을 큐에 두 번 넣지 않는다(넣지 않은 곡 수를 알린다).
- 목표: 일부러 열어 저장하면 다시 저장된다. 이미 저장한 곡의 편집 화면에는 "다시 저장하면 '파일'에 하나 더 생겨요"를 보인다.
- 비목표: '파일'의 기존 중복 정리, 덮어쓰기(웹에서 불가), 기록 지우기 화면.
- 피할 것: 기록을 못 쓰거나 못 읽어도(사생활 모드·용량) 앱이 멈추는 것.

## 방식

| 방식 | 장단점 |
|---|---|
| **A. 저장할 때 원본·결과 파일의 이름+크기를 localStorage에 기억 (선택)** | 날이 바뀌어도, 결과 파일을 다시 넣어도 알아본다. 홈 화면 앱을 지우면 기록도 지워진다 |
| B. 큐 안 중복만 막기 | 이번 보고(날을 바꿔 다시 넣음)를 못 막는다 |

## 정한 것

- **기록:** 키 `크기:이름`, 값은 저장 시각(ISO). 저장이 끝나면(markSaved) 원본(source 이름·바이트 길이)과 결과 파일(이름·크기) 두 키를 쓴다. 읽기·쓰기 실패는 무시.
- **다시 넣은 파일:** 기록에 있으면 파일을 읽은 뒤 status 'saved', `savedBefore`=시각. 검색·자동 분석은 하지 않는다. 분석이 파일에 있으면 'done', 없으면 'skipped'(“이전에 저장한 곡이라 분석하지 않았어요”)이고 [다시 분석]으로 돌릴 수 있다. 직접 검색(🔍)·수정·다시 분석을 하면 지금처럼 '저장 필요'로 돌아간다.
- **표시:** 상태 글자 '이전에 저장함 (M/D)'. [저장된 곡 지우기]에 함께 들어간다(status 'saved').
- **큐 안 중복:** 같은 `크기:이름`이 이미 큐에 있으면 넣지 않고 "이미 큐에 있는 N곡은 빼고 넣었어요".
- **편집 화면:** status 'saved'면 저장 버튼 위에 "저장한 곡이에요. 다시 저장하면 '파일'에 하나 더 생겨요".
